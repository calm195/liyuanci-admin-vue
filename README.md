# 鲤源池 Web 管理端

内容审核与词库管理默认连接契约 0.2.0 的真实接口；词库支持分类 heads 基准、完整快照、双版本发布及归档只读详情。

## 1. 项目介绍

鲤源池后台管理 Web 应用，采用 Vue 3 Composition API、Vite、严格 TypeScript、Vue Router、Pinia 和 Element Plus。提供后台登录入口、角色菜单、工作台、后台账号管理、平台用户查询、身份审核、内容审核及举报／处罚／申诉管理及危机工作台。

后台采用超管预建本地账号，登录后可本人改密。登录、本人改密、退出、账号管理、身份审核、内容审核、词库、举报／处罚／申诉管理及危机工作台直接连接同源 HTTP 接口，开发和生产构建行为一致。身份审核分离查询列表、只读案件详情和处理抽屉，支持按需读卡、通过/驳回及回执，内容审核同样分离只读详情与处理抽屉，按案件版本提交决定并独立展示业务结果；授权危机升级从详情显式打开独立操作。代码不提供本地演示账号、案件或词库。

超级管理员使用独立的证据删除与回执查询页面。删除页读取已知证据元信息，显式打开处理抽屉后填写理由，按证据范围版本二次确认整范围删除；受理后凭待办 ID 前往回执查询，也可使用本人提供的完整匿名回执查询。删除受理不代表物理清理完成；正文、学号和回执不保存到浏览器存储。

管理界面使用统一侧栏、顶部面包屑和按角色过滤的菜单。登录页及工作区均支持浅色、深色和跟随系统；仅主题偏好保存在浏览器本地存储，存储不可用时仍可切换。页面标题及面包屑来自路由元数据，Element Plus 组件显式导入并配置简体中文。

账号查询与编辑通过右侧抽屉分离；词单列表、只读详情和草稿创建使用独立路由，发布在详情页二次确认。举报、处罚与申诉分别使用独立页面，查询及只读详情与处理抽屉分离；处罚页按本页已确认举报查询依据，当前接入接口没有处罚历史列表。

树洞审核位于 `/whispers/reviews`，使用独立 `whispers/1.0.0` 契约，按帖子、暖评、昵称和私密胶囊展示命中案件。列表、只读详情与处理抽屉分离，决定提交案件和正文双版本；内容判定与实际公开、昵称启用或胶囊解锁结果分开展示。审核运营及超管可进入，普通审核详情升级危机仅向超管开放，所有动作仍受服务端投影和授权约束。后端未提供新接口时显示真实错误；危机后续处置页面另行接入。

树洞举报位于 `/whispers/reports`，三类案件角色均可按授权查询；列表、只读详情和处理抽屉分离。治理对象与版本来自举报来源，确认举报后才可按轻微警告、一般禁言7天、严重永久封禁进行处罚，无需填写作者账号或版本。解除普通限制不会直接公开内容；危机升级仅危机岗位及超管按服务端动作开放。树洞来源的处罚申诉继续使用既有申诉工作台，不增加私密原文或身份字段。

树洞危机位于 `/whispers/crises`，仅危机岗位与超管可读取限定正文、认证状态、时间线和投递状态，并按服务端动作接手、跟进、结案、重试有效通知或标记误报。未认证时显示“尚无认证学号”；结案不解除隔离，误报转普通复核不等于公开。超管在 `/whispers/evidence` 按已知范围 ID 读取元信息，输入 `DELETE_EVIDENCE_SCOPE` 及理由后受理整个范围删除，再按返回任务 ID 手动查询清理进度；受理不代表完成。正文、处理理由及重试请求仅保留在页面内存，撤权、换号与离页清理。

## 2. 项目选项与目录结构

管理端直接访问同源 `/api/v1`，无需公开环境开关。开发服务通过 Vite 代理转发至本机 `18080` 后端；生产托管须配置同源反向代理。`VITE_` 变量为公开配置，不得包含秘密。

```text
src/
  assets/       全局样式和静态资源
  components/   可复用 UI 组件（按需创建）
  composables/  可复用响应式行为
  router/       懒加载路由、角色菜单与守卫
  services/     外部 I/O 与数据校验边界
  stores/       共享状态与后台内存会话
  types/        共享领域及契约类型
  utils/        纯函数与相邻测试
  views/        路由级页面
public/         公共静态资源
```

现状、缺陷与后续计划统一见 [管理端文档索引](../docs/development/admin/README.md)。

## 3. 项目启动方式

使用 Node.js `^22.13.0 || >=24.0.0` 和 pnpm 10（项目声明版本为 10.34.6），保留 `pnpm-lock.yaml`。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

默认 `pnpm dev` 和生产构建均连接同源 `/api/v1`，无需 integration 模式或额外开关。账号管理仅超管可用；创建账号的初始口令由服务端策略提供，页面不设置或显示口令。部署方需提供同源后台路由；身份审核需后端装配人工认证接口。内容审核与词库使用真实接口；安全治理页面支持举报确认／驳回、账号警告／固定 7 天禁言／永久封禁、申诉维持／撤销，以及普通内容下线／解除限制。三类后台角色可访问普通案件；角色管理仍仅超管可用。处罚账号版本和内容处置资源版本需从授权交接取得，页面不使用案件或正文版本代替。危机工作台的查询列表、只读详情与处理抽屉分离，仅危机角色及超管可用，支持限定证据、时间线、关怀／人员通知待办、接手／跟进／结案、通知重试及误报转普通复核；举报与审核详情支持按权限升级。后端需显式提供独立 `CrisisDSN` 才注册危机接口；未装配时页面展示错误并支持重试。工作台只显示关怀投递状态，不读取学生专属关怀卡正文，也不内置援助资料。

质量检查与构建预览：

```sh
pnpm format
pnpm check
pnpm build
pnpm preview
```

`pnpm check` 包含格式、零警告 ESLint、类型检查与测试。单独执行测试可用 `pnpm test`，监听模式用 `pnpm test:watch`。

`pnpm lint` 自动检查非测试 JS/TS（含 JSX/TSX）、Vue、独立 CSS/HTML 和工程脚本，覆盖 Vue 样式块、HTML 内联样式块与脚本：禁止任务、需求及里程碑编号，说明注释必须包含中文，`console`、`logger`、`log` 的常见日志方法首参必须是包含中文的字符串或模板，动态数据作为后续参数。日志检查按作用域追踪对象和方法的赋值、解构、链式别名、命名导入别名与 `bind/call/apply`，重赋值保守保留日志来源；禁止通过动态属性或跨模块转发绕过检查，新增日志封装须扩展规则与用例。保留三斜线类型引用指令；文件名为 `*.spec.*`、`*.test.*` 或位于 `__tests__/` 的测试文件（含 HTML 内联脚本）豁免此规则。`pnpm test` 同时执行业务测试与规范检查器回归测试；`pnpm test:watch` 仅监听业务测试。

## 4. 开发规范与须知

非测试代码不得出现里程碑、任务或需求编号；追踪信息仅写入docs当前文档或测试。代码注释只使用中文说明功能与业务意图、边界及设计原因，日志和面向用户的错误提示使用中文。语言指令、接口字段、协议值及工具要求的标识符保留原文。

Vue 3.5.44 的属性校验器声明通过 `patches/` 中的单行补丁兼容 Element Plus 与 `exactOptionalPropertyTypes`：允许运行时已支持的显式 `undefined` 校验器，不改变校验函数签名或运行时代码。升级 Vue 时应重新核对该补丁。

使用 `<script setup lang="ts">`，遵循严格类型与现有格式、lint 规则，不使用 `any`、不安全断言或抑制注释绕过检查。外部数据在 services 边界校验；瞬时 UI 状态留在组件，共享状态才进入 store；行为测试与实现相邻存放。

业务源码修改后依次运行 `pnpm format`、`pnpm check`、`pnpm build`；需要自动 lint 修复时使用 `pnpm lint:fix`。纯文档整理执行格式、链接、固定输入及差异检查。准确记录验证结果与未完成依赖。

README 仅维护项目介绍、项目选项与目录结构、启动方式、开发规范与须知，并同步英文版。现状、缺陷与后续计划由 docs 工程集中维护；本工程不保留阶段文档。

源码与 docs 的本地和远程仅保留 `develop`、`main`，日常开发均使用 `develop`；变动前核对两仓库分支和工作区，并行任务协调写入范围，必要时使用 detached 工作树并在汇总后清理。docs每端仅滚动维护现状、缺陷和后续计划，引用完整源码提交；旧阶段材料从Git历史追溯，不再新增阶段报告；详见 [文档管理规范](../docs/governance/README.md)。按功能提交且须有用户授权，不自动 push、部署或上线；需求、审批及固定设计只读。

后台令牌仅存内存，刷新需重新登录，不接学生会话，不在浏览器存储身份资料。菜单和按钮隐藏不能替代后端授权。禁止提交凭据、本地 Codex 认证或私有环境值。

生产静态托管需 HTTPS、history fallback 和同源 `/api/v1` 反向代理，禁止缓存敏感 API 响应。完整项目约定见 [AGENTS.md](AGENTS.md)。

浏览器回归：先运行 `pnpm dev --host 127.0.0.1 --port 5173 --strictPort`，再运行 `pnpm test:browser`。测试需要可解析的 Playwright 和已安装的 Chrome；可用 `PLAYWRIGHT_MODULE` 指定已有模块绝对路径，用 `ADMIN_TEST_BROWSER_CHANNEL` 选择已有浏览器通道，用 `ADMIN_TEST_OUTPUT` 指定证据目录。脚本只访问本机页面并拦截全部业务接口为合成响应，覆盖双主题、桌面/窄屏、抽屉、角色菜单与会话清理；不能代替真实后端联调。

平台用户入口为 `/users`，支持昵称与状态组合筛选、游标分页、详情和授权处罚历史。普通处罚从案件工作台确认，核对时重新读取账号版本；昵称查询仅保存在内存中。需要后端启用 `admin-users/1.0.0` 的三个 GET，接口不可用时显示错误。用户页面浏览器回归使用 `pnpm test:browser:users`，环境参数与上述浏览器回归一致。

超级管理员可在平台用户详情直接封禁/解封、禁言/取消禁言，需填写理由并二次确认。禁言固定7天，解除按当前类型生效。该能力需要后端显式应用0028迁移并提供 `user-restrictions/1.0.0` 接口。

资料管理入口为 `/resources` 和 `/resource-categories`，仅审核运营与超管可用，消费 `resource-plaza/1.0.1` 的10个后台接口。已上架资料须先下架才能编辑，保存后显式上架；支持分类维护与四类当前版本反馈汇总。资料正文、链接、提取码及待重试命令仅存内存，接口不可用时明确显示错误。浏览器合成回归运行 `pnpm test:browser:resources`，环境参数同上；真实后端与三端联调需另行验证。

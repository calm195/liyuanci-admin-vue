# 鲤源池 Web 管理端

内容审核与词库管理默认连接契约 0.2.0 的真实接口；词库支持分类 heads 基准、完整快照、双版本发布及归档只读详情。

## 1. 项目介绍

鲤源池后台管理 Web 应用，采用 Vue 3 Composition API、Vite、严格 TypeScript、Vue Router、Pinia 和 Element Plus。提供后台登录入口、角色菜单、工作台、后台账号管理、身份审核、内容审核及举报／处罚／申诉管理及危机工作台。

后台采用超管预建本地账号，登录后可本人改密。登录、本人改密、退出、账号管理、身份审核、内容审核、词库、举报／处罚／申诉管理及危机工作台直接连接同源 HTTP 接口，开发和生产构建行为一致。身份审核支持按需读卡、通过/驳回及回执，内容审核按案件版本提交决定并独立展示业务结果。代码不提供本地演示账号、案件或词库。

超级管理员可在证据删除与回执页面读取已知证据条目的元信息，使用证据范围版本及删除理由确认整范围删除，查询后台待办和匿名删除回执。删除受理不代表物理清理完成；页面不保存正文、学号或回执到浏览器存储。

管理界面使用统一侧栏、顶部面包屑和按角色过滤的菜单。登录页及工作区均支持浅色、深色和跟随系统；仅主题偏好保存在浏览器本地存储，存储不可用时仍可切换。页面标题及面包屑来自路由元数据，Element Plus 组件显式导入并配置简体中文。

账号查询与编辑通过右侧抽屉分离；词单列表、只读详情和草稿创建使用独立路由，发布在详情页二次确认。举报、处罚与申诉分别使用独立页面，查询及只读详情与处理抽屉分离；处罚页按本页已确认举报查询依据，当前接入接口没有处罚历史列表。

## 2. 项目选项与目录结构

管理端直接访问同源 `/api/v1`，无需公开环境开关。开发服务通过 Vite 代理转发至本机 `18080` 后端；生产托管须配置同源反向代理。`VITE_` 变量为公开配置，不得包含秘密。

```text
src/
  assets/       全局样式和静态资源
  components/   可复用 UI 组件（按需创建）
  composables/  可复用响应式行为
  router/       懒加载路由、角色菜单与守卫
  services/     外部 I/O 与数据校验边界
  stores/       共享状态与后台内存会话
  types/        共享领域及契约类型
  utils/        纯函数与相邻测试
  views/        路由级页面
public/         公共静态资源
```

开发过程、阶段记录及验证证据统一见 [管理端文档索引](../docs/development/admin/README.md)。

## 3. 项目启动方式

使用 Node.js `^22.13.0 || >=24.0.0` 和 pnpm 10（项目声明版本为 10.34.6），保留 `pnpm-lock.yaml`。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

默认 `pnpm dev` 和生产构建均连接同源 `/api/v1`，无需 integration 模式或额外开关。账号管理仅超管可用；创建账号的初始口令由服务端策略提供，页面不设置或显示口令。部署方需提供同源后台路由；身份审核需后端装配人工认证接口。内容审核与词库使用真实接口；安全治理页面支持举报确认／驳回、账号警告／固定 7 天禁言／永久封禁、申诉维持／撤销，以及普通内容下线／解除限制。三类后台角色可访问普通案件；角色管理仍仅超管可用。处罚账号版本和内容处置资源版本需从授权交接取得，页面不使用案件或正文版本代替。危机工作台仅危机角色及超管可用，支持限定证据、时间线、关怀／人员通知待办、接手／跟进／结案、通知重试及误报转普通复核；举报与审核详情支持按权限升级。后端需显式提供独立 `CrisisDSN` 才注册危机接口；未装配时页面展示错误并支持重试。工作台只显示关怀投递状态，不读取学生专属关怀卡正文，也不内置援助资料。

质量检查与构建预览：

```sh
pnpm format
pnpm check
pnpm build
pnpm preview
```

`pnpm check` 包含格式、零警告 ESLint、类型检查与测试。单独执行测试可用 `pnpm test`，监听模式用 `pnpm test:watch`。

`pnpm lint` 自动检查非测试 JS/TS（含 JSX/TSX）、Vue、独立 CSS/HTML 和工程脚本，覆盖 Vue 样式块、HTML 内联样式块与脚本：禁止任务、需求及里程碑编号，说明注释必须包含中文，`console`、`logger`、`log` 的常见日志方法首参必须是包含中文的字符串或模板，动态数据作为后续参数。日志检查按作用域追踪对象和方法的赋值、解构、链式别名、命名导入别名与 `bind/call/apply`，重赋值保守保留日志来源；禁止通过动态属性或跨模块转发绕过检查，新增日志封装须扩展规则与用例。保留三斜线类型引用指令；文件名为 `*.spec.*`、`*.test.*` 或位于 `__tests__/` 的测试文件（含 HTML 内联脚本）豁免此规则。`pnpm test` 同时执行业务测试与规范检查器回归测试；`pnpm test:watch` 仅监听业务测试。

## 4. 开发规范与须知

非测试代码不得出现里程碑、任务或需求编号；追踪信息仅写入阶段文档或测试。代码注释只使用中文说明功能与业务意图、边界及设计原因，日志和面向用户的错误提示使用中文。语言指令、接口字段、协议值及工具要求的标识符保留原文。

Vue 3.5.44 的属性校验器声明通过 `patches/` 中的单行补丁兼容 Element Plus 与 `exactOptionalPropertyTypes`：允许运行时已支持的显式 `undefined` 校验器，不改变校验函数签名或运行时代码。升级 Vue 时应重新核对该补丁。

使用 `<script setup lang="ts">`，遵循严格类型与现有格式、lint 规则，不使用 `any`、不安全断言或抑制注释绕过检查。外部数据在 services 边界校验；瞬时 UI 状态留在组件，共享状态才进入 store；行为测试与实现相邻存放。

每组修改后依次运行 `pnpm format`、`pnpm check`、`pnpm build`；需要自动 lint 修复时使用 `pnpm lint:fix`。准确记录验证结果与未完成依赖。

README 仅维护项目介绍、项目选项与目录结构、启动方式、开发规范与须知，并同步英文版。过程产物由 docs 工程集中管理；本工程不保留阶段文档。

管理端后续开发基于 `develop`，对应 docs 分支为 `admin-develop`；变动前核对两仓库分支和工作区，docs 有其他任务时使用独立工作树。固定阶段记录不再修改，后续交付、勘误和补证据在 docs 对应端新增文件，并引用完整源码提交；详见 [文档管理规范](../docs/governance/README.md)。按功能提交且须有用户授权，不自动 push、部署或上线；需求、审批及固定设计只读。

后台令牌仅存内存，刷新需重新登录，不接学生会话，不在浏览器存储身份资料。菜单和按钮隐藏不能替代后端授权。禁止提交凭据、本地 Codex 认证或私有环境值。

生产静态托管需 HTTPS、history fallback 和同源 `/api/v1` 反向代理，禁止缓存敏感 API 响应。完整项目约定见 [AGENTS.md](AGENTS.md)。

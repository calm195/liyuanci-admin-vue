## Identity review business page (2026-10-21)

The second stage connects `src/views/IdentityView.vue` and renames its menu to Identity Review. Lists support loading, retry, empty results and cursor navigation. Case details and the synthetic card load on demand. Approval/rejection includes confirmation, versioned submission and readable receipts; processed and unknown states are read-only. Rejection requires trimmed reason and suggestion. Pending submissions block duplicates; unchanged retries reuse the idempotency key. A 409 clears the old decision and reloads the case without resubmitting.

Details, forms, images and receipts remain component-local. Switching cases, paging, refreshing, closing, leaving or changing sessions/permissions clears data and cancels requests. Local generations discard late results. Blob URLs are revoked on hiding, image failure and cleanup. A 401 clears the session; a 403 clears identity data and uses existing denial navigation. Backend response bodies are never displayed directly. The service contains only synthetic data, with no real network or persistent storage. Re-entering resets synthetic cases, unlike real persisted reviews.

Service-stage validation passed 32 behavioral tests. Page-stage validation passed 46 behavioral tests (14 new component cases), 58 rule tests, `pnpm format`, `pnpm check` and `pnpm build`. The browser showed a synthetic approved receipt at version 2; a screenshot was saved in a local temporary directory. This is not real identity-review acceptance. Manual steps are in `docs/T012-integration.md`. Both README introductions and Mock options were updated. Contract remains 0.1.0; no new dependencies.

## Business service boundaries (2026-10-21)

The user authorized business implementation ahead of T011 readiness, replacing the earlier sequencing restriction on page development. Real integration acceptance conditions remain unchanged. Traceability: REQ-002/018/019; contract 0.1.0; branch `codex/identity-review`.

The first stage adds `src/types/identity.ts` and `src/services/identity.ts`: projected cursor lists, authorized case details, a local synthetic card, approved/rejected decisions and Verification receipts. Every operation rechecks local permission. Rejection requires trimmed reason and suggestion. Version/state conflicts return 409. Matching idempotency keys replay matching receipts, while different content conflicts; replay rechecks authorization. Allowlist parsers prevent full identity fields from reaching list state.

The card contains only synthetic demonstration content. Production fails closed. This does not establish real server persistence, audit or case authorization. D02/T008/T011 and real card binary type, size and cache headers remain pending integration; no real adapter is enabled in this stage.

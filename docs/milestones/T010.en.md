# T010

## Session concurrency boundaries (2026-10-21)

Traceability: T010, REQ-018/019; shared contract 0.1.0. This stage completes boundaries in the existing session implementation, then awaits D02/T008 real login and T011 acceptance rather than bypassing the prerequisites for T012. Development branch: `codex/admin-session-lifecycle`.

- A login superseded by logout or a newer login explicitly fails, preventing the caller from proceeding with a successful navigation.
- Requests bind both the session object and a local generation. Even if a new login reuses the same session object, old results and 401/403 responses cannot affect the current session.
- Logout still clears locally before revocation. An old revocation failure cannot overwrite a new login's notice. A failure in the current generation still reports that server revocation is unconfirmed.

Module boundaries: only the local lifecycle in `src/stores/admin.ts` and its behavioral tests change. Server authorization, API fields, role rules and memory-only storage remain unchanged. No dependencies were added. The local generation distinguishes successive operations; it is not a server token version or proof of authorization.

Validation: `pnpm format`, `pnpm check` and `pnpm build` passed, with 25 behavioral tests and 58 ESLint rule tests. Five new synthetic regression cases cover logout interrupting login, competing logins, an old logout failure, and late 401/403 responses. No real backend or manual browser acceptance was performed.

Pending dependencies: D02 login fields remain unfrozen; T008 real session and T011 private-card, case authorization, audit and version-consistency acceptance evidence have not been delivered. T010 is not accepted as real integration. T012 remains a preparation page, with T017/T028/T030/T032 following their original prerequisites. See `docs/contract-questions.md` for integration questions and `docs/T012-integration.md` for readiness conditions.

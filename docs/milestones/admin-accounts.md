## 主要行为

- `/accounts` 懒加载页面及“后台账号管理”菜单仅超级管理员可进入，审核运营、危机角色及空角色均不可访问；未登录回登录页。
- 列表显示账号名、启用/停用、三类角色和目标版本，标注本人。limit=20，不透明游标原样编码，提供上一页、下一页和从首页刷新。列表动态变化，不声称冻结快照；写入成功重新读取首页。
- 创建输入账号名、角色数组和非空理由，允许空角色。核对账号/角色/理由后二次确认，提交期间禁止重复点击。不提供初始口令输入、返回口令或重置口令入口；初始口令由服务端仓库外策略处理，经指定渠道交付。
- 角色完整替换使用选中目标 Account.version，允许移除所有角色和修改本人，不新增最后超管限制。修改前展示目标账号、版本、新角色与理由；本人修改特别提示移除超管后离开页面。
- 相同输入遇网络失败后沿用同一 Idempotency-Key，输入改变才创建新命令。409/404不自动重放，重新读取首页、清除旧编辑目标，要求重新选择并确认；创建409保留输入和幂等键，避免因刷新盲目换键创建。
- 本人修改成功即把服务端返回的 Account 更新到当前内存会话，菜单立即按最新角色刷新；失去超管权限清空页面、触发403路由但保留仍有效的会话，不自动续期。不推断其他账号当前浏览器会话的角色，后端继续逐请求授权。
- 401清会话与页面；403清页面、停止操作并进入拒绝页，不推导新角色。离页、会话切换及本地撤权取消在途请求、丢弃旧响应，列表和理由不持久化。

## 模块与接口边界

`src/types/accounts.ts` 定义输入、分页和客户端；`src/services/accounts.ts` 负责 HTTP、封装和运行时字段校验，额外令牌/口令等字段被丢弃；`AccountsView.vue` 维护临时表单、分页历史、确认和重试标识。共享 `useAdminWorkspace` 增加目标角色参数，默认仍为审核运营；账号页面明确指定 super_admin，保留原审核页面行为。

| 方法与路径（前缀 /api/v1）     | 请求                                                                | 成功                                 |
| ------------------------------ | ------------------------------------------------------------------- | ------------------------------------ |
| GET /admin/accounts            | limit=20、可选 cursor、后台 Bearer                                  | 200，标准封装 data.items/next_cursor |
| POST /admin/accounts           | login_name、roles、reason；后台 Bearer 与稳定 Idempotency-Key       | 201，标准封装 Account，无口令        |
| PUT /admin/accounts/{id}/roles | roles、reason、expected_version；后台 Bearer 与稳定 Idempotency-Key | 200，标准封装目标 Account            |

所有响应先检查 code=0/message/request_id/data，再校验账号/分页字段。允许 active=false 和 roles=[] 的管理投影，拒绝未知角色、非法版本及跨目标角色回执。请求同源、no-store、credentials=omit、redirect=error，支持 AbortSignal；发起、响应及读体后复核本地授权与取消。错误正文不显示或记录，保留 HTTP 状态用于安全提示。

## 运行状态与设计取舍

账号页面只有真实 HTTP 接线及测试桩，不新增合成账号管理模型。沿用显式身份联调开关：`VITE_ADMIN_MOCK=false VITE_ADMIN_AUTH_INTEGRATION=true pnpm dev --mode integration`。需后端 opt-in 启用后台身份和账号路由、迁移/权限齐备、同源 /api/v1 转发与仓库外隔离超管；默认、Mock、生产构建保持入口关闭。本轮没有增加独立新开关、依赖、代理或后台身份读取/续期接口。

此接线是前端已实现能力，不等于已完成真实 HTTP 联调。内容审核、词库仍为 Mock；举报/处罚/申诉、危机、证据、技术工作项仍无页面，上一轮功能清单的其他状态保持适用。本人改密服务虽有隔离传输，其页面现有启用条件仍仅 Mock，本阶段未调整该独立页面。

## 验证结果

`pnpm format`、`pnpm check`、`pnpm build` 均通过。16 个业务测试文件、171 个测试，以及规范检查器58个测试通过。新增账号传输/页面回归并扩展路由与环境准入：覆盖字段筛选、空角色/停用投影、分页编码、201/200、稳定幂等键、目标版本、二次确认、重复提交、网络重试、409刷新复核、401/403、跨账号回执、取消/撤权及本人角色同步。

## 未完成依赖

没有可用的同源隔离后端/超管身份，未执行真实服务、数据库/Redis、审计、并发或三端联调；这些由后端和集成方提供。初始口令交付、账号名唯一性、当前角色授权、回执重放及留迹原子性仍由服务端执行，本端测试不代替后端验收。后台 TTL 仍由协调方明确。本轮只修改本仓库并提交，不 push、部署或上线。

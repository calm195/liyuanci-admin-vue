## Implementation and boundaries

`types/admin.ts` defines account/login/password fields and whitelists requests without trimming passwords or inventing complexity/length policy. `services/admin-auth-transport.ts` is an explicitly injected protocol adapter with two fixed same-origin paths, no cache/cookies/redirects, no login Bearer/key, and current Bearer/caller key for password changes. It accepts only 204 without parsing a body and never echoes backend error text. It is not wired into runtime; tests use a substitute fetch and do not establish real service acceptance.

Runtime `services/admin.ts` fails closed outside explicit DEV Mock. Random temporary credentials and the single current fixture live only in module memory: no built-in password, actual account provisioning, persistent hash or browser storage. Roles configure fixture accounts; login only accepts account/password. Several tokens may authenticate to the same fixture. Successful password change clears all old synthetic tokens; an incorrect current password changes nothing. Revoked-token retries return 401 before replay. These are in-process synthetic semantics, not database atomicity, cross-process revocation or audit evidence.

The store binds login/password operations to session identity and generation. A 204 clears the session and requests login; current 401 clears it; stale success/errors never alter a new session. Wrong-current-password 403 does not trigger global role-forbidden navigation. The password route is available to any authenticated admin. It locks duplicate submissions, reuses the key for identical uncertain retries and changes it for changed input. A 403 clears inputs; session changes/unmount abort requests and clear passwords/keys. Cancellation does not roll back server operations; eventual real integration must confirm via session verification/login without automatic resubmission.

LoginView supports account/password input only in explicit DEV Mock, with temporary fictional credential generation and optional reveal for a complete password-change/login preview. Submission clears the password; unmount aborts login and clears input. No automatic renewal or forced initial change is added. T012 production code is untouched; only session test projections gain login_name. Wordlist services/pages are unchanged, with shared session fixtures updated. README reflects the settled policy and preview steps.

# T017 Content moderation and wordlists

## Service boundaries (2026-10-21)

Traceability: REQ-015/019 (REQ-018 for write boundaries); shared contract 0.1.0. The user authorized business implementation ahead of real integration. Branch: `codex/content-moderation-wordlists`. Commit order: service boundaries, content review/ordinary restrictions, then wordlist pages, each with tests and bilingual stage records.

`src/types/moderation.ts` and `src/types/wordlists.ts` define lists, cases, ReviewDecision, ModerationOutcome, ReasonCommand and wordlist inputs/outputs. `src/services/review-boundary.ts` shares validation and synthetic authorization/idempotency; `moderation.ts` and `wordlists.ts` own page-local synthetic business instances. No dependencies, identity-review changes, browser persistence or real requests. Explicit DEV Mock is required; production fails closed.

Review displays matched body at its exact content_version and rejects outdated case versions. Content decisions and business execution outcomes remain distinct. Synthetic cases cover ordinary/school content, revised content, cancelled interactions, privacy review and a matched message. No conversation traversal or global private-chat search. Ordinary offline/release commands require reasons and resource versions; release leaves content withdrawn without republishing.

Wordlists support crisis/school/ordinary_violation. New categories omit expected_version; existing ones require the current version to create a draft. Creation never publishes. The synthetic model uses the highest category resource version as its creation basis, increments version on publication and archives earlier published items. This is not a frozen server version model. Unknown states are read-only in the UI.

Wordlist lacks existing entries, authoritative creation basis and active-version linkage. No real adapter is enabled.

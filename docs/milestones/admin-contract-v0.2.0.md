## 实际实现与边界

`types/admin.ts` 定义账号名、登录和本人改密输入，并只提取请求字段，口令不trim、不施加未经确认的复杂度/长度产品门槛。`services/admin-auth-transport.ts` 是显式注入传输的协议适配器：仅两个固定同源路径，无缓存/cookie/重定向；登录不带授权/幂等键，改密带当前Bearer和调用方key，204不解析body，非预期状态不当成功，不回显后端正文。它未接入运行时，回归使用替代fetch，不能冒充真实服务通过。

运行时 `services/admin.ts` 在生产/非显式Mock始终失败关闭；DEV合成凭据由randomUUID临时生成，单个当前夹具保存在模块内存，没有内置口令、真实账号创建、密码摘要持久化或浏览器存储。生成角色只配置虚构账号，loginAdmin仅接收账号/口令。多个合成token可登录同一夹具；改密成功清空旧token集合，旧口令错误不改会话；撤销后的重试先401，不绕过授权重放。这只是本进程合成状态，不代表服务端原子事务、跨进程撤销或审计有效。

store按会话对象和代次保护登录/改密；204清会话并提示重新登录，当前401清会话，旧请求的成功/错误均不能影响新会话。本人旧口令403不触发全局角色越权页。PasswordView为所有已登录后台角色可访问的本人操作，表单防重复、相同输入结果未明重试沿用key，改输入换key；403清输入；会话变化/离开取消并清口令及key。取消不意味着服务端操作回滚，真实接线后须重读/重登确认，不自动重发。

LoginView显示账号/口令表单，只有显式DEV合成入口可提交；可生成并选择显示临时虚构凭据用于完整改密/重登演示。提交结束清口令，离开取消登录并清输入；不增加自动续期/首登强改密。T012业务代码未改，只有测试会话投影补账号名；词库服务/页面未改，只有共用会话测试投影更新。README同步当前登录政策和演示方式。
